Most interview problems are variations on a small number of techniques. Learning to **recognise the pattern** is worth more than memorising any individual solution — and it is what turns an unfamiliar problem into a familiar one.

This page maps every technique in the guide to the problems that teach it.

## The Recognition Table

## The Patterns

### 1. Hash Map / Set — trade memory for time

Turn an `O(n)` search into an `O(1)` lookup. The single highest-leverage move in this guide.

[Two Sum](/docs/arrays/two-sum) · [Contains Duplicate](/docs/arrays/contains-duplicate) · [Group Anagrams](/docs/arrays/group-anagrams) · [Valid Anagram](/docs/strings/valid-anagram) · [Minimum Index Sum](/docs/arrays/minimum-index-sum-of-two-lists) · [Unique Email Addresses](/docs/strings/unique-email-addresses)

### 2. Two Pointers — converging

Start at both ends and move inward under a rule that provably discards possibilities.

[Container With Most Water](/docs/arrays/container-with-most-water) · [Valid Palindrome](/docs/strings/valid-palindrome) · [Trapping Rain Water](/docs/arrays/trapping-rain-water)

### 3. Two Pointers — same direction

Both pointers move forward, at different rates or under different conditions.

[Is Subsequence](/docs/strings/is-subsequence) · [Remove Duplicates II](/docs/arrays/remove-duplicates-from-sorted-array-ii) · [Merge Sorted Array](/docs/arrays/merge-sorted-array)

### 4. Fast & Slow Pointers

One pointer moves twice as fast. Finds middles, detects cycles, locates offsets.

[Middle of the Linked List](/docs/linked-lists/middle-of-the-linked-list) · [Linked List Cycle II](/docs/linked-lists/linked-list-cycle-ii) · [Intersection of Two Lists](/docs/linked-lists/intersection-of-two-linked-lists)

### 5. Sliding Window

A range that slides or grows across the data. The two kinds behave differently and are worth separating.

| | Fixed size | Variable size |
|---|---|---|
| Trigger | "subarray of size `k`" | "longest / shortest such that…" |
| Left edge | Moves every step | Moves only when the rule breaks |
| Example | [Maximum Average Subarray I](/docs/arrays/maximum-average-subarray-i) | [Longest Substring Without Repeating](/docs/strings/longest-substring-without-repeating-characters) |

### 6. Prefix / Suffix Precomputation

One pass forward, one pass back, then combine. Turns range queries into `O(1)` arithmetic.

[Running Sum](/docs/arrays/running-sum-of-1d-array) · [Find Pivot Index](/docs/arrays/find-pivot-index) · [Product of Array Except Self](/docs/arrays/product-of-array-except-self) · [Candy](/docs/greedy/candy) · [Trapping Rain Water](/docs/arrays/trapping-rain-water)

### 7. Stack

Last-in-first-out. Nesting, undo, deferred operands, depth-first traversal.

[Valid Parentheses](/docs/stacks-queues/valid-parentheses) · [Min Stack](/docs/stacks-queues/min-stack) · [Evaluate RPN](/docs/stacks-queues/evaluate-reverse-polish-notation) · [Simplify Path](/docs/stacks-queues/simplify-path)

#### Monotonic stack

A stack deliberately kept sorted, so anything breaking the order is popped. Answers "next greater" questions in one pass instead of `O(n²)`.

[Daily Temperatures](/docs/stacks-queues/daily-temperatures) · [Trapping Rain Water](/docs/arrays/trapping-rain-water)

### 8. BFS / DFS

Queue for breadth, stack for depth. The choice determines both the visit order and the space cost.

[Level Order Traversal](/docs/trees/binary-tree-level-order-traversal) · [N-ary Preorder](/docs/trees/n-ary-tree-preorder-traversal) · [Number of Islands](/docs/graphs/number-of-islands) · [Course Schedule](/docs/graphs/course-schedule) · [Maximum Depth](/docs/trees/maximum-depth-of-binary-tree) · [Jump Game II](/docs/greedy/jump-game-ii)

### 9. Binary Search

Halve the search space. Works for exact matches, for boundaries, and even when there is no array.

[Binary Search](/docs/searching/binary-search) · [Search Insert Position](/docs/searching/search-insert-position) · [First Bad Version](/docs/searching/first-bad-version)

### 10. Greedy vs. Dynamic Programming

Greedy when the local choice is provably safe; DP when it is not.

[Jump Game](/docs/greedy/jump-game) · [Gas Station](/docs/greedy/gas-station) · [Candy](/docs/greedy/candy) · [Integer to Roman](/docs/strings/integer-to-roman) · [Climbing Stairs](/docs/dynamic-programming/climbing-stairs) · [House Robber](/docs/dynamic-programming/house-robber) · [Coin Change](/docs/dynamic-programming/coin-change) · [Longest Increasing Subsequence](/docs/dynamic-programming/longest-increasing-subsequence)

<Callout type="info" title="Coin Change is the clearest greedy-vs-DP boundary">
With coins `[1, 3, 4]` and a target of `6`, greedy takes the `4` and needs three coins. The best answer is `3 + 3`, using two.

Whenever a local choice can block a better option later, greedy is unsafe and DP is the answer.
</Callout>

### 11. Heap — keep the best k reachable

A heap answers one question fast: what is the smallest right now? That is enough for "top k" and "next to process".

[Kth Largest](/docs/heaps/kth-largest-element-in-an-array) · [Merge k Sorted Lists](/docs/heaps/merge-k-sorted-lists) · [Top K Frequent](/docs/arrays/top-k-frequent-elements)

### 12. Backtracking — choose, explore, undo

For problems asking for **all** arrangements. Always exponential, so the constraints will be small.

[Subsets](/docs/backtracking/subsets) · [Permutations](/docs/backtracking/permutations) · [Combination Sum](/docs/backtracking/combination-sum)

## Complexity Cheat Sheet

| Notation | Meaning | Example |
|---|---|---|
| `O(1)` | constant | hash map lookup |
| `O(log n)` | halving each step | binary search |
| `O(n)` | one pass | a single loop |
| `O(n log n)` | sorting | comparison sorts |
| `O(n²)` | nested loops | brute-force pairs |
| `O(2ⁿ)` | branching recursion | unmemoized subsets |

<Callout type="info" title="Constraints tell you the target complexity">
`n ≤ 10⁵` rules out `O(n²)` — that would be 10 billion operations. It points at `O(n)` or `O(n log n)`.

`n ≤ 20` is small enough for exponential, which usually means the intended solution is backtracking or bitmasking.

Reading the constraints first often tells you which technique the author had in mind.
</Callout>
